01 Thứ tự ưu tiên khi có xung đột

  1. Bảo toàn dữ liệu và config của user.
  2. Làm đúng cái user yêu cầu.
  3. Tôn trọng các ràng buộc/loại trừ user đã nêu.
  4. Thay đổi nhỏ nhất, đúng nhất.
  5. Verify đúng hành vi được yêu cầu.
  6. Báo cáo rủi ro không liên quan phát hiện được — không tự sửa.
  7. Dừng lại khi task được yêu cầu đã xong.

Không được làm (trừ khi user yêu cầu rõ cho từng việc)

  • Refactor/cleanup/optimization/security-hardening/migration không liên quan đến task.
  • Sửa code đang chạy ổn định ngoài luồng được yêu cầu.
  • Bịa thêm requirement, đoán API contract/DB column/response service ngoài.
  • Rename "cho đẹp", move file "tổ chức lại", đổi pattern vì sở thích, upgrade dependency không ai hỏi, reformat cả file, xoá code "unused" chưa chứng minh.
  • Tắt/xoá test hoặc làm yếu assertion chỉ để build xanh.
  • Gọi hệ thống/thiết bị thật (API đối tác, thiết bị chấm công, DB production) khi chưa được yêu cầu rõ cho lần đó — có credential không có nghĩa là được phép.

Refactor chỉ hợp lệ khi

  • User yêu cầu rõ ràng, hoặc
  • Không refactor thì không thể hoàn thành task an toàn, hoặc
  • Hoàn toàn cục bộ và không đổi hành vi ra ngoài luồng đang sửa.

Phát hiện vấn đề ngoài phạm vi → không sửa → ghi nhận riêng như 1 observation → tiếp tục task được giao → chỉ implement sau khi user duyệt riêng.

02 Bảo vệ config & secret — rule tuyệt đối

Không bao giờ xoá / làm rỗng / ghi đè / khôi phục / sanitize / thay thế / mã hoá / di dời (User Secrets, env var…) / đổi tên key / reformat 1 file config chứa giá trị thật — kể cả khi cách làm "sạch hơn" có vẻ hiển nhiên tốt hơn — trừ khi user duyệt rõ ràng cho đúng lần đó. Không copy .Example.json đè file thật, không git checkout/restore/reset --hard/clean nhắm vào file config, không restore từ git.

Nếu phát hiện secret thật trong file tracked

Không xoá/mask/rotate, không in giá trị ra log/docs/diff/test output — chỉ báo: đường dẫn file, tên key, tình trạng Configured / Missing, rủi ro, và phương án cần user duyệt trước khi làm.

03 Hệ thống phải an toàn — checklist cho code mới

Lấy pattern đúng của Face (project duy nhất tuân thủ đủ) đối chiếu với bad pattern đã audit thật — dùng làm target, không phải mô tả hiện trạng chung.

Network & Auth

  • CORS — whitelist domain cụ thể, không bao giờ AllowAnyOrigin()/SetIsOriginAllowed(_ => true) ở bất kỳ environment nào.
  • JWT — bật đủ 4 validation: Issuer, Audience, Lifetime, IssuerSigningKey.
  • Auth theo route, không chỉ theo group — kiểm tra từng endpoint có bị .AllowAnonymous() đè lên .RequireAuthorization() hay không.
  • Swagger chỉ Development, không public Production.
  • Rate limit endpoint nhạy cảm: login, seed data, upload sinh trắc học, reset password.

Data & Query

  • Raw SQL — không nội suy giá trị chưa escape vào FromSqlRaw; tên cột sort/filter động phải whitelist.
  • EF Core — không EnableSensitiveDataLogging()/EnableDetailedErrors() vô điều kiện; không UseLazyLoadingProxies().
  • Secret tại rest — mật khẩu thiết bị… mã hoá bằng ASP.NET Data Protection trước khi lưu DB.
  • Không log secret/PII/dữ liệu sinh trắc học thô — chỉ log tên field + trạng thái.
  • appsettings — chỉ commit appsettings.Example.json placeholder; file chứa giá trị thật phải .gitignore (nợ kỹ thuật hiện tại: gần như mọi project đang commit thẳng — xem Memory).
Tham chiếu "làm đúng trông như thế nào" → dùng Face. ZKTime có rule ghi ra nhưng code thật chưa sửa theo — đừng dùng ZKTime làm mẫu.

01 Nền tảng

coding.md — Tech stack & naming convention C# · TypeScript
Backend: .NET 8/9, Nullable + ImplicitUsings mặc định, EF Core 8/9, MediatR 13–14 (codebase CQRS), Carter 8.x, Serilog (codebase mới) hoặc ILogger<T> thuần.
Frontend: Angular 18–21, 100% standalone, TypeScript strict, Tailwind v4 CSS-first hoặc CSS token thuần, Signal API cho state mới.
  • PascalCase class/interface(I)/enum/method/property; camelCase local/param; method async luôn hậu tố Async.
  • Command/Query: <Verb><Entity>Command/Query, handler hậu tố Handler; Carter module <Entity>Api : ICarterModule.
  • Angular: input()/output() thay @Input/@Output, OnPush, inject(), control-flow gốc @if/@for, không .mutate() trên signal.
  • Một số codebase cũ vẫn RxJS-first dù Angular mới — signal là hướng đi tới, không bắt buộc rewrite.
architecture.md — Dependency direction & layer boundary Clean Architecture
Chain đã xác nhận thật (4/7 BE: Device, Ops, ZKTime, Face — Face đầy đủ nhất):
Domain ← Contract ← Application ← { Infrastructure, Persistence } ← Presentation ← Api
  • Kiểu đặc thù hạ tầng (SqlException, HTTP client cụ thể…) không được lộ ra khỏi Persistence/Infrastructure — case chuẩn: UnitOfWork.SaveChangesAsync bắt mã lỗi 2601/2627 convert thành domain exception.
  • Vi phạm thật đã thấy: Device's JwtAuthorizeAttribute.cs nằm trong Application nhưng reference HttpContext — bug kiến trúc, không phải style.
  • CIO, CSR: Endpoint→Service→DbContext trực tiếp — hợp lệ, không bắt buộc đổi. TaskFlow: có Carter nhưng logic nằm ở Persistence — hiện trạng thật, không tự "sửa cho đúng".
  • Device/protocol integration (Hikvision ISAPI…) phải sau 1 interface + DelegatingHandler riêng, không rò logic protocol vào Application/Domain.
security.md — Checklist hệ thống + bảo vệ config rule tuyệt đối

git.md — Không phá config bằng lệnh git rộng
  • Không git checkout -- <file>/restore/clean/reset --hard nhắm vào config mà chưa được duyệt rõ cho lần đó — kể cả để "dọn working tree cho sạch".
  • Trước lệnh git có thể xoá thay đổi chưa commit: chạy git status trước, stash/commit nếu cần.
  • Không convention commit riêng nào ghi lại trong audit — mặc định Conventional Commits nếu project chưa có style khác.
  • Chỉ tạo commit khi user yêu cầu; review lại git status/diff đã stage trước khi commit, kể cả tên file trông vô hại.
testing.md — AAA baseline, SQL Server thật cho concurrency
  • Arrange-Act-Assert baseline cho unit test mới, không ép % coverage cụ thể.
  • Test invariant DB (filtered unique index) phải chạy SQL Server thật, không EF Core InMemory — InMemory không enforce unique index, pass giả dù logic sai.
  • Không claim "hoạt động trên thiết bị thật" chỉ từ 1 field trạng thái DB — cần bằng chứng test/log thiết bị thật.
  • FE test stack không đồng nhất — xem bảng ở tab Memory.

02 Backend — .rules/backend/

api.md

Carter ICarterModule là pattern chiếm ưu thế (Device/Ops/ZKTime/Face/TaskFlow); CIO/CSR dùng minimal API thuần — hợp lệ. Route versioned /api/v{version}/<resource>. RequireAuthorization() ở group không đảm bảo route con được bảo vệ — bug thật ở Ops (DepartmentApi.cs).

error-handling.md

logging.md

Pattern đã xác nhận & bad pattern đã audit

Tổng hợp từ audit thật: PROJECT_AUDIT.md (CIO), review_pj.md/PHASE1 (Device), BACKEND_ARCHITECTURE_ANALYSIS.md (Ops), ARCHITECTURE.md + FINAL_PROJECT_AUDIT/REAUDIT (ZKTime). Đây là snapshot tại thời điểm audit — luôn grep xác nhận code thật trước khi dùng làm căn cứ.

01 Pattern chung đã xác nhận

  • Result / Result<T> tại <Project>.Contract/Abstractions/Shared/Result.cs — CIO, CSR, Device, Ops, ZKTime, Face (không có ở TaskFlow).
  • AsNoTracking() cho mọi read query — nhất quán ở cả 7 project.
  • Migration thủ công, không auto-migrate lúc startup — TaskFlow's fail-fast (throw nếu còn pending migration) là pattern nên nhân rộng.
  • Filtered unique index chống trùng/race condition ở tầng DB — Ops, ZKTime, Face, TaskFlow.
  • 100% Angular standalone component, không NgModule nào trong toàn bộ 7 FE.
  • ngx-toastr có mặt ở 6/7 FE (trừ TaskFlow).

04 Ghi chú vận hành

Nguồn gốc nội dung

Rules trong .rules/ không phải lý thuyết áp đặt — đúc kết từ audit thực tế source code + tài liệu audit (PROJECT_AUDIT.md, review_pj.md, ARCHITECTURE.md, FINAL_PROJECT_AUDIT/REAUDIT…) của cả 7 project, cộng với 2 file CLAUDE.md viết tay chi tiết nhất workspace (Face, TaskFlow).

Khi rule và code thực tế của 1 project lệch nhau (vd ZKTime), rule ghi rõ trạng thái thật, không giả vờ project đó đã tuân thủ.

Golden rule

Không được skip gate: đọc context → phân tích → review → implement → test → QA. Nếu fail thì quay lại phase phù hợp, không tuyên bố "xong" khi test còn fail.
