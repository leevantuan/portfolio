02 Feature Implementation — 2 bản mô tả song song

.skills/common/feature-implement/SKILL.md

8 phase: Requirement → Audit → Impact Analysis → Implementation Plan → Second-Pass Review → Implement → Testing → Final QA. Dừng ở mỗi phase, không code trước khi hiểu yêu cầu.

1
Requirement

Behavior, user flow, AC, edge case — chưa code.

2
Audit

Component/service/API/DB liên quan đã có, tái dùng tối đa.

3
Impact Analysis

FE/BE/API/DB/auth/perf/security/responsive/test/docs.

4
Implementation Plan

File tạo/sửa, data flow, validation, migration.

5
Second-pass Review

Missing requirement, security, regression risk.

6
Implement

Tối thiểu, giữ hành vi hiện có, không rewrite ngoài luồng.

7
Testing

Happy path + edge + regression; fail → investigate → fix → retest.

8
Final QA

Đúng AC, không thay đổi thừa, docs cập nhật nếu cần.

01 Nền tảng

coding.md — Tech stack & naming convention C# · TypeScript
Backend: .NET 8/9, Nullable + ImplicitUsings mặc định, EF Core 8/9, MediatR 13–14 (codebase CQRS), Carter 8.x, Serilog (codebase mới) hoặc ILogger<T> thuần.
Frontend: Angular 18–21, 100% standalone, TypeScript strict, Tailwind v4 CSS-first hoặc CSS token thuần, Signal API cho state mới.
  • PascalCase class/interface(I)/enum/method/property; camelCase local/param; method async luôn hậu tố Async.
  • Command/Query: <Verb><Entity>Command/Query, handler hậu tố Handler; Carter module <Entity>Api : ICarterModule.
  • Angular: input()/output() thay @Input/@Output, OnPush, inject(), control-flow gốc @if/@for, không .mutate() trên signal.
  • Một số codebase cũ vẫn RxJS-first dù Angular mới — signal là hướng đi tới, không bắt buộc rewrite.
architecture.md — Dependency direction & layer boundary Clean Architecture
Chain đã xác nhận thật (4/7 BE: Device, Ops, ZKTime, Face — Face đầy đủ nhất):
Domain ← Contract ← Application ← { Infrastructure, Persistence } ← Presentation ← Api
  • Kiểu đặc thù hạ tầng (SqlException, HTTP client cụ thể…) không được lộ ra khỏi Persistence/Infrastructure — case chuẩn: UnitOfWork.SaveChangesAsync bắt mã lỗi 2601/2627 convert thành domain exception.
  • Vi phạm thật đã thấy: Device's JwtAuthorizeAttribute.cs nằm trong Application nhưng reference HttpContext — bug kiến trúc, không phải style.
  • CIO, CSR: Endpoint→Service→DbContext trực tiếp — hợp lệ, không bắt buộc đổi. TaskFlow: có Carter nhưng logic nằm ở Persistence — hiện trạng thật, không tự "sửa cho đúng".
  • Device/protocol integration (Hikvision ISAPI…) phải sau 1 interface + DelegatingHandler riêng, không rò logic protocol vào Application/Domain.
security.md — Checklist hệ thống + bảo vệ config rule tuyệt đối

Không bao giờ xoá/làm rỗng/ghi đè/di dời 1 giá trị config thật (API key, connection string, credential thiết bị…) mà không có chấp thuận rõ ràng cho từng lần của user — kể cả khi cách làm "sạch hơn" có vẻ hiển nhiên tốt hơn. Phát hiện secret thật trong file tracked → không xoá/mask/rotate, không in giá trị ra log/docs/diff — chỉ báo path file, tên key, tình trạng Configured/Missing và chờ duyệt.

Network & Auth
  • CORS whitelist domain cụ thể, không bao giờ AllowAnyOrigin().
  • JWT bật đủ 4 validation: Issuer, Audience, Lifetime, IssuerSigningKey.
  • Auth theo route — kiểm tra .AllowAnonymous() có đè .RequireAuthorization() không.
  • Swagger chỉ Development, rate limit endpoint nhạy cảm (login, seed data, upload sinh trắc học).
Data & Query
  • Không nội suy giá trị chưa escape vào FromSqlRaw; cột sort/filter động phải whitelist.
  • Không EnableSensitiveDataLogging()/EnableDetailedErrors() vô điều kiện; không UseLazyLoadingProxies().
  • Không log secret/PII/dữ liệu sinh trắc học thô — chỉ log tên field + trạng thái.
workflow.md — Staged delivery, quyết định đã chốt, audit read-only
  • Giao hàng theo giai đoạn: xong 1 giai đoạn → dừng → báo cáo (đã làm gì / build-test pass hay fail / còn gì chưa xong) → chờ xác nhận.
  • Quyết định đã chốt trong CLAUDE.md hoặc hội thoại trước không tự ý lật lại — cần lý do kỹ thuật, giải thích trước khi đổi, ghi ngày tháng.
  • Hệ thống/thiết bị thật: mặc định KHÔNG gọi API đối tác, thiết bị chấm công, DB production — có credential không đồng nghĩa được dùng.
  • Audit-only session: chụp git status trước/sau, không migration/build sinh side-effect, không request ghi, DB chỉ SELECT.
git.md — Không phá config bằng lệnh git rộng
  • Không git checkout -- <file>/restore/clean/reset --hard nhắm vào config mà chưa được duyệt rõ cho lần đó — kể cả để "dọn working tree cho sạch".
  • Trước lệnh git có thể xoá thay đổi chưa commit: chạy git status trước, stash/commit nếu cần.
  • Không convention commit riêng nào ghi lại trong audit — mặc định Conventional Commits nếu project chưa có style khác.
  • Chỉ tạo commit khi user yêu cầu; review lại git status/diff đã stage trước khi commit, kể cả tên file trông vô hại.
testing.md — AAA baseline, SQL Server thật cho concurrency
  • Arrange-Act-Assert baseline cho unit test mới, không ép % coverage cụ thể.
  • Test invariant DB (filtered unique index) phải chạy SQL Server thật, không EF Core InMemory — InMemory không enforce unique index, pass giả dù logic sai.
  • Không claim "hoạt động trên thiết bị thật" chỉ từ 1 field trạng thái DB — cần bằng chứng test/log thiết bị thật.
  • FE test stack không đồng nhất — xem bảng ở tab Memory & Audit.

02 Backend — .rules/backend/

api.md

Carter ICarterModule là pattern chiếm ưu thế (Device/Ops/ZKTime/Face/TaskFlow); CIO/CSR dùng minimal API thuần — hợp lệ. Route versioned /api/v{version}/<resource>. RequireAuthorization() ở group không đảm bảo route con được bảo vệ — bug thật ở Ops (DepartmentApi.cs).

database.md

Migration áp dụng thủ công, không Database.Migrate() lúc startup ở bất kỳ project nào. TaskFlow's fail-fast check (throw nếu còn pending migration) là pattern tốt nhất, nên nhân rộng. FK/cột filter-sort-join bắt buộc có index cùng migration.

error-handling.md

Result<T> ở 6/7 project (trừ TaskFlow). Vấn đề thật: service khai báo trả Result nhưng vẫn throw exception cho lỗi nghiệp vụ dự kiến được (CIO/CSR/Device) → 2 con đường lỗi song song, 2 hình dạng JSON khác nhau cho cùng API.

logging.md

Serilog: Device/Ops/ZKTime/Face; ILogger<T> thuần: CIO/CSR/TaskFlow — cả 2 hợp lệ. Case Ops: có UseSerilog() nhưng thiếu section config. Không log secret/PII/sinh trắc học thô. Correlation-ID chưa tồn tại ở project nào — nếu thêm là tính năng mới, không phải khôi phục.

performance.md

Không UseLazyLoadingProxies() — N+1 ẩn đã xác nhận ở Device/ZKTime. List endpoint dữ liệu lớn phải phân trang server-side, không trả full dataset cho FE tự cắt. Retry/resilience chỉ cho lỗi transient thật, không retry mù mọi exception.
